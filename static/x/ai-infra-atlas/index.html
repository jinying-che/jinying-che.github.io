COMPUTE

GPU 利用率 ≠ 有效工作率

高 utilization 不代表每秒产出的有效 token 或训练样本最多。还需结合 MFU（特定训练场景）、HBM 带宽、显存占用、kernel stall 与最终吞吐。

NETWORK

带宽之外，还要看拓扑

Collective 让慢链路 / 单个异常 rank 波及所有参与 GPU。应看 NCCL 时延、PFC/ECN（RoCE 场景）、重传、拥塞与拓扑放置。

STORAGE

Checkpoint 是恢复机制

不仅考察写入速度，还需测「保存时间、恢复时间、恢复正确性、失败时损失的训练进度」。异步保存可降阻塞，但增加内存与并发管理约束。

07 — INCIDENT THINKING

看 4 个事故，就知道 AI SRE 在排什么

排障核心从「服务是否存活」延伸到「业务是否产出有效 token / step」。以下是诊断框架，不是对特定故障的唯一原因判断。

INCIDENT / 01 · TRAINING

多卡训练突然卡死，GPU 还在占用

告警：Step time 停止前进，部分 rank 卡在 collective

优先观察：各 rank 最后成功的 collective、NCCL 超时、GPU Xid/ECC、网络端口错误、慢节点 / 不一致的并行配置。

系统动作：关联 rank ↔ Pod ↔ GPU ↔ NIC，隔离坏节点，按 checkpoint 恢复；后续加入 admission 及拓扑校验。

INCIDENT / 02 · INFERENCE

请求成功率没掉，但 TTFT p99 飙升

告警：排队上升，长 prompt 流量占比变高

优先观察：request queue、输入长度分布、prefill time、KV cache 空间、prefix cache 命中、模型副本冷热状态。

系统动作：按 workload 调整批处理与扩缩容 / routing；评估 prefill-decode 分离是否值得额外 KV 传输成本。

INCIDENT / 03 · PLATFORM

GPU 集群仍有闲置，训练 Job 却排队

告警：ClusterQueue pending，若干节点有空闲卡

优先观察：Quota、resource flavor、gang 全量需求、节点拓扑、GPU 型号 / MIG 切分、污点 / 亲和性。

系统动作：衡量碎片与队列等待成本，选择更合适的拓扑、配额借用、抢占或多集群分发策略。

INCIDENT / 04 · DATA

训练吞吐周期性下跌，日志显示 checkpoint

告警：Checkpoint 耗时变长 / 共享存储写入被打满

优先观察：存储吞吐和 p99、训练 worker 同时写入、CPU memory / staging、恢复用的 checkpoint 完整性。

系统动作：评估分片、分布式 / 异步 checkpoint、限流、缓存与恢复 RTO；避免只提高磁盘吞吐而不测恢复。

08 — LEARNING BY BUILDING

90 天路线：做出可展示的 AI Infra 项目

学习方式以「可复现部署 → 可解释指标 → 可制造故障 → 可优化成本」为主。没有 GPU 时，先完成软件层与监控层；再租用短时间单卡做性能实验。

DAY 01–14 / FOUNDATION

认知与最小服务

  • 理解 GPU / HBM / PCIe、CUDA、模型权重、token / KV
  • 容器里跑小模型 / vLLM（有兼容 GPU 时），提供 OpenAI-compatible API
  • 做基线：并发、TTFT、tokens/s

DAY 15–30 / CLUSTER

进入 GPU 资源管理

  • Kubernetes + GPU Operator / Device Plugin

  • 接入 DCGM exporter 与 Prometheus / Grafana

DAY 31–60 / RELIABILITY

做一次真排障

  • 注入排队压力、Pod 重启、模型冷启动 / OOM
  • 训练方向尝试 PyTorch DDP / 小模型的 checkpoint 恢复
  • 建立 SLI / SLO、运行手册与告警规则
交付：故障演练录屏 + RCA + 优化前后数据

  • 平台：Quota / Gang / topology-aware scheduling
  • 性能：通信、存储或 GPU profiling

Collectives / NCCL跨设备的数据聚合和交换；通信耗时、同步与异常 rank 会影响全局训练进度。
RDMA / RoCE / IB低 CPU 参与的数据移动技术 / 以太网 RDMA 技术 / 网络技术体系，概念层次不同。
Gang Scheduling多 worker 作业需成组具备资源才运行；Kueue 以 quota admission、TAS、readiness 等机制组合近似 all-or-nothing，不保证配额准入后立即全部运行。
Checkpoint训练状态（不仅是权重）的可恢复快照，其保存、加载和恢复正确性都需要衡量。
Prefill / Decode先处理输入 prompt 并建立 KV 状态，再逐 token 生成；两阶段的资源瓶颈不同。
KV Cache推理 attention 计算的中间状态，不是普通对象存储；显存压力决定可承载并发和上下文。
TTFT / ITL / TPOT首输出延迟 / 流式输出间隔 / 单请求平均输出 token 时间；观测点与聚合方式必须写清楚。
